There's no Kubernetes 3.0. The version numbering hasn't changed — we're at Kubernetes 1.36 as of May 2026, and the project is still going strong. But the conversation keeps coming up because each release brings changes that feel major enough to deserve a "3.0" label.

Here's what actually happened in the recent releases worth knowing about.

## Kubernetes 1.35 (January 2026)

This was a substantial release with 44 enhancements — 14 GA, 18 beta, 12 alpha.

**ML job orchestration went beta.** The MLJob API provides a first-class abstraction for distributed training and batch inference with gang scheduling and fault tolerance. This matters because it means Kubernetes can natively schedule ML training jobs without custom controllers or third-party operators.

**Cluster-level automation went GA.** You can now declaratively manage node pools, feature gates, and component versions. The control plane reconciles drift automatically. This is a big deal for fleet operations — managing hundreds of clusters becomes manageable when you can declare the desired state of your entire fleet.

**Network observability went beta.** Standard metrics for traffic flow, policy decisions, and latency mean consistent interfaces across service meshes, gateways, and CNI plugins. No more vendor-specific dashboards for basic network visibility.

**WASM workload integration went beta.** You can now run WebAssembly workloads on Kubernetes using RuntimeClass. Not ready for critical production yet, but the foundation is there.

**KMS v3 went GA.** Automatic key rotation and multi-provider envelope encryption for secrets. If you're running production Kubernetes, this is a significant security upgrade.

## Kubernetes 1.36 (May 2026)

The latest release focuses on API quality and hardware scheduling.

**Declarative validation went GA.** This replaces thousands of lines of handwritten validation code with a unified framework. For users, it means more predictable APIs and fewer validation bugs. The new `validation-gen` code generator reads `+k8s:` tags and automatically generates validation functions.

**SELinux volume mounting improvements went GA.** Instead of recursive file relabeling (slow), the system now uses `mount -o context=XYZ` at mount time. Faster pod startup on SELinux systems.

**DRA support for partitionable devices.** A single GPU can now be split into multiple logical units shared across workloads. This directly addresses the problem of GPU underutilization — dedicating an entire 80GB A100 to a small inference workload is wasteful.

**externalIPs deprecation.** The `externalIPs` field on Services is finally being deprecated due to CVE-2020-8554 (man-in-the-middle attacks). Full removal in 1.43.

**gitRepo volume type disabled.** This was deprecated since 1.11. It's now permanently disabled due to a critical security issue where attackers could run code as root via gitRepo volumes.

## What About Kubernetes 3.0?

The "3.0" rumor started because some people expected a major version bump when significant architectural changes landed. But the Kubernetes project has been clear: there are no plans for a 3.0. The 1.x numbering continues.

What has changed is the scope of what Kubernetes handles. It started as a container orchestrator. In 2026, it's a platform that orchestrates containers, VMs, WASM modules, ML training jobs, and GPUs. The underlying architecture supports all of these through the same API primitives — pods, controllers, schedulers.

If that's not a 3.0 level of evolution, I don't know what is. The version number just hasn't caught up.

## What to Do

Upgrade to 1.36 if you haven't already. The security improvements alone are worth it — KMS v3, SELinux fixes, gitRepo removal, and externalIPs deprecation all reduce your attack surface. The ML and WASM features are worth evaluating for new workloads, but don't rush production migrations until they've had more time to mature.
